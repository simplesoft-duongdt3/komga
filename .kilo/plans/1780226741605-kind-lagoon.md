# Plan: Fix Series bookCount Mismatch & Book Navigation Bugs

## Root Causes

### Issue 1: Series `bookCount = 0` but detail shows books

**`bookCount` and `NUMBER_SORT` are only set during `sortBooks()`**, but several code paths that add/remove books never call it. When `addBooks()` creates BookMetadata, `numberSort` defaults to `0` for all books (since books have `number = 0`), causing ordering issues in the UI alongside the zero bookCount.

| Code path | File:Line | What happens |
|-----------|-----------|--------------|
| `POST /api/v1/series` (create + add books) | `SeriesController.kt:694-708` | `addBooks()` inserts books but never calls `sortBooks()` → bookCount=0, NUMBER_SORT=0 for all |
| `POST /api/v1/series/{id}/books` (add to existing) | `SeriesController.kt:745` | `addBooks()` inserts books but never calls `sortBooks()` |
| `tryRestoreBooks()` during scan | `LibraryContentLifecycle.kt:577` | Restores books from trash without updating bookCount |
| Scan with `scanDeep=false`, no disk changes | `LibraryContentLifecycle.kt:291` | Series not added to `seriesToSortAndRefreshList` → `sortBooks` never called |

**Key code locations:**
- `SeriesLifecycle.kt:115-118` — `sortBooks()` is the ONLY place `bookCount` and `NUMBER_SORT` get set for existing books
- `SeriesLifecycle.kt:121-149` — `addBooks()` creates `BookMetadata` with `numberSort = book.number.toFloat()` (typically 0, since new books have no number yet)
- `LibraryContentLifecycle.kt:343-353` — `sort_and_refresh_series` phase calls `sortBooks()` only for series in the refresh list

### Issue 2: Books cannot move next/forward

**`findSiblingSeries()` in `BookDtoDao.kt:322-346` does NOT filter out soft-deleted books.** The `selectBase()` used in the sibling query has no `WHERE b.DELETED_DATE IS NULL`. When a series contains soft-deleted books (normal — they occur when files are moved/deleted on disk during scan), the navigation may:

1. Return a soft-deleted book as the next/previous sibling
2. The frontend receives `deleted: true` but still attempts to navigate → appears broken

**Key code location:**
- `BookDtoDao.kt:338-346` — `findSiblingSeries()` query missing `b.DELETED_DATE.isNull`

## Implementation Plan

### Step 1: Fix `addBooks()` to call `sortBooks()` at the end

**File**: `komga/src/main/kotlin/org/gotson/komga/domain/service/SeriesLifecycle.kt`

After all books are inserted and events published, call `sortBooks()` which renumbers books, updates `NUMBER_SORT`/`NUMBER` in metadata, and updates `bookCount`:

```kotlin
// At end of addBooks(), after the eventPublisher loop:
sortBooks(series)
```

This replaces the current behavior where `bookCount` stays 0 and `NUMBER_SORT` defaults to 0 for all new books.

### Step 2: Fix `sortBooks()` to count non-deleted books only

**File**: `komga/src/main/kotlin/org/gotson/komga/domain/service/SeriesLifecycle.kt`

In `sortBooks()` (line 117), change from counting ALL books to counting only non-deleted books:

```kotlin
// Current (line 117):
seriesRepository.update(it.copy(bookCount = books.size), false)

// Fixed:
seriesRepository.update(it.copy(bookCount = books.count { b -> b.deletedDate == null }), false)
```

### Step 3: Fix `findSiblingSeries()` to exclude deleted books

**File**: `komga/src/main/kotlin/org/gotson/komga/infrastructure/jooq/main/BookDtoDao.kt`

Add `b.DELETED_DATE.isNull` to the sibling query (after line 340):

return dslRO

### Step 4: Add `fixSeriesBookCount()` method to SeriesLifecycle

**File**: `komga/src/main/kotlin/org/gotson/komga/domain/service/SeriesLifecycle.kt`

This method calls `sortBooks()` on each specified series. `sortBooks()` already handles everything we need: renumbers books, updates `NUMBER_SORT` and `NUMBER` in `BookMetadata`, and updates `SERIES.BOOK_COUNT`.

```kotlin
fun fixSeriesBookCount(vararg seriesIds: String) {
  val targets = if (seriesIds.isEmpty()) {
    seriesRepository.findAll().filter { it.deletedDate == null }
  } else {
    seriesIds.mapNotNull { seriesRepository.findByIdOrNull(it) }
  }

  targets.forEach { series ->
    sortBooks(series)
  }
}
```

> **Note**: The full `sortBooks()` path triggers `taskEmitter.refreshBookMetadata()` for books whose numbering changed, which may schedule additional background tasks. This is intentional — it ensures metadata consistency.

### Step 5: Add REST endpoint to trigger the fix per-library

**File**: `komga/src/main/kotlin/org/gotson/komga/interfaces/api/rest/LibraryController.kt`

Inject `SeriesLifecycle` into constructor (currently has `seriesRepository` but not `seriesLifecycle`). New admin endpoint:

```kotlin
@PostMapping("{libraryId}/fix-book-counts")
@PreAuthorize("hasRole('ADMIN')")
@ResponseStatus(HttpStatus.ACCEPTED)
@Operation(summary = "Fix book counts and numbering for all series in a library")
fun fixBookCounts(@PathVariable libraryId: String) {
  val series = seriesRepository.findAllByLibraryId(libraryId).filter { it.deletedDate == null }
  seriesLifecycle.fixSeriesBookCount(*series.map { it.id }.toTypedArray())
}
```

### Step 6: Add REST endpoint for single series fix

**File**: `komga/src/main/kotlin/org/gotson/komga/interfaces/api/rest/SeriesController.kt`

SeriesController already has `seriesLifecycle` injected. New endpoint:

```kotlin
@PostMapping("{seriesId}/fix-book-count")

@Operation(summary = "Fix book count and renumber books for a series")
fun fixSeriesBookCount(
  @PathVariable seriesId: String,
  @AuthenticationPrincipal principal: KomgaPrincipal,

  seriesLifecycle.fixSeriesBookCount(seriesId)
}
```
