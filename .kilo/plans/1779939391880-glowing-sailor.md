# Hash Cache UI — Generate, Summary, and Download from Frontend

> Add hash cache management to the smart-scanner web UI. Users can trigger
> `pdf-hasher` generation for a selected library, watch live progress via SSE,
> see a summary of the result, and download the generated cache file.

---

## 1. Current State

- `pdf-hasher` Rust binary is baked into the `smart-scanner` Docker image
- The binary is only usable via CLI: `docker compose run --rm smart-scanner pdf-hasher --root ...`
- No UI exposure — users must know the library UUID and construct the command manually
- Cache files live at `{HASH_CACHE_DIR}/hashes-{library_id}.json`

---

## 2. Goal

Expose hash cache management directly in the web UI so a user can:

1. See if a cache exists for a library and its size/stats
2. Generate (or regenerate) the cache with a button click, watching live progress
3. Download the current cache file

### 3.2 Backend (`server.py`)

Three new endpoints:

#### `GET /api/hash-cache/{library_id}`

Returns cache file summary info (does NOT trigger generation).

```json
{
  "exists": true,
  "path": "/exports/hashes-a1b2c3d4.json",
  "total_files": 500000,
  "total_bytes": 12500000000000,
  "generated_at": "2026-05-26T10:00:00Z",
  "elapsed_secs": 1234.5,
  "file_size_bytes": 133456789,
  "library_root": "/data"
}
```

Errors: `404` if cache doesn't exist, `404` if library not found via Komga API.

#### `POST /api/hash-cache/{library_id}`

Spawns `pdf-hasher` as a subprocess and streams output via SSE.

Request body (optional):
```json
{ "threads": 4 }
```
Defaults to `config.HASHER_THREADS` (env `HASHER_THREADS`, default `4`).

SSE event types:

| Event | Fields | When |
|---|---|---|
| `phase` | `{ phase: "walking"|"classifying"|"hashing"|"writing" }` | Phase transition |
| `progress` | `{ line: "... raw output line ..." }` | Each stdout line from pdf-hasher |
| `stat` | `{ key: "total_files"|"to_hash"|..., value: number\|string }` | Parsed stat from output |
| `done` | `{ success: true, ... }` or `{ success: false, error: "..." }` | Process exit |

Implementation:
- Resolve library ID → root path via Komga API (`list_libraries()`)
- Strip `file://` prefix from root
- Construct cache path: `os.path.join(HASH_CACHE_DIR, f"hashes-{library_id}.json")`
- Spawn: `subprocess.Popen(["pdf-hasher", "--root", root, "--cache", cache_path, "-j", str(threads)], stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True)`
- Read stdout line-by-line, wrap in SSE `data:` events
- Parse key lines to emit `stat` events for structured display
- On process exit (success or failure), emit `done` event

**Key parsing logic** — extract stats from known pdf-hasher stdout patterns:

| stdout pattern | Extracted stat |
|---|---|
| `Found \d+ .pdf files` | `total_files` |
| `Status: \d+ skip.* \d+ new, \d+ changed — \d+ to hash` | `skip, new, changed, to_hash` |
| `Hashed \d+ files \(\d+ bytes new\) in \d+.\d+s` | `hashed, hashed_bytes, hashed_secs` |
| `Stale entries removed: \d+` | `stale` |
| `Cache written to .+ \(\d+ entries\)` | `entries_written` |
| `Total: \d+ files, .+ MB, \d+.\d+s .+ MB/s` | `total_summary` |

### 3.3 Frontend (`app.js` + `index.html`)

No HTML changes needed — all rendering is dynamic via app.js.

**State additions** (in `state` object):
```js
hashPanel: null,        // library_id of the currently-open hash panel
hashCacheInfo: null,    // result from GET /api/hash-cache/{id}
hashGenerating: false,  // true when SSE stream is active
hashLog: [],            // accumulated progress lines
hashStats: {},          // parsed structured stats
```

**New function: `renderHashPanel(library)`**

Rendered as an inline panel below Step 1's library grid. Shows:
1. Skeleton/message to select a library
2. Cache info section (when loaded): exists state, file count, bytes, age
3. Generate button
4. Download button (when cache exists)
5. Progress/log area (when generating)

**New function: `loadHashCacheStatus(libraryId)`**

Calls `GET /api/hash-cache/{libraryId}`, populates `state.hashCacheInfo`, renders panel.

**New function: `generateHashCache(libraryId, threads)`**

Calls `POST /api/hash-cache/{libraryId}`, reads SSE stream, renders progress.

Uses `fetch()` with response body reader (same pattern as `executeScript()` in existing code at `app.js:439-468`). For each SSE event:
- `phase` → update phase indicator
- `progress` → append to log area (auto-scroll)
- `stat` → update structured stat counters
- `done` → finalize, enable download button, re-fetch cache status

## 5. Edge Cases

| Case | Handling |
|---|---|
| Library not found in Komga | Return 404 from backend, show error in panel |
| Cache file doesn't exist yet | GET returns `{ exists: false }`, UI shows "No cache — generate one?" |
| pdf-hasher binary not found | Subprocess error caught → `done { success: false, error: "..." }` SSE event |
| Generation already running | `hashGenerating` state flag + backend could add PID check. For MVP: disable button while running. |
| Very large log output | Cap displayed log at last 50 lines; auto-scroll |
| Library root is not a valid path | Backend validates path exists before spawning subprocess |
| Long-running generation (hours) | SSE keeps connection open. Browser timeout concerns: use periodic heartbeat events. |

## 7. Decisions

1. **Thread count**: Default to `4`, overridable via `HASHER_THREADS` env var. Add to `config.py` and `docker-compose.yml`. Matches the existing `-j 4` manual workflow.

2. **Stderr merging**: `subprocess.Popen` merges stderr into stdout (`stderr=subprocess.STDOUT`). When stderr is not a TTY (subprocess capture), `indicatif` emits newline-based progress output — visible as text in the SSE log.

3. **Heartbeat**: Send SSE comment events (`: heartbeat\n\n`) every 15 seconds via `asyncio.sleep` while the subprocess is running. Prevents proxy/browser timeouts during multi-hour generations.

4. **Concurrency**: Disable the "Generate" button globally when any generation is in progress. Backend tracks this via `is_generating` flag. Running two `pdf-hasher` instances would thrash I/O for zero benefit — `pdf-hasher` already uses rayon for full parallelism.
