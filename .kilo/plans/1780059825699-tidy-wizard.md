# Rust Rewrite — Komga Smart Scanner

> Rewrite `scan-library-tool` (Python/FastAPI) into a single Rust binary
> (`rust-scan-library-tool`) with the same behavior, web UI, and diff logic.

---

## 1. Goals

1. **Single Rust binary** — no Python runtime, no pip, one `cargo build --release`
2. **Same functional behavior** — identical diff results, same curl scripts, same SSE streams
3. **Keep existing web UI** — reuse `static/index.html` + `static/app.js` verbatim (they call `/api/*` endpoints, language-agnostic)
4. **Integrate pdf-hasher** — merge the existing Rust `pdf-hasher` as a library into the main binary (shared hash cache format)
5. **Docker deployment** — single-stage `rust:alpine` with musl static binary
6. **SQL query compatibility** — read the same Komga PostgreSQL tables (case-sensitive column names `"ID"`, `"NAME"`, etc.)

---

## 2. Technology Choices

| Layer | Python (old) | Rust (new) | Rationale |
|---|---|---|---|
| Web framework | FastAPI + Uvicorn | **Axum** | Async, SSE native, tower middleware ecosystem, most popular Rust web framework |
| HTTP client | `requests` | **reqwest** | De facto standard, async, connection pooling |
| PostgreSQL | `psycopg2` | **sqlx** | Compile-time SQL verification, async, `FromRow` derive |
| XXH3 hashing | `xxhash` (Python) | **xxhash-rust** | Already used by pdf-hasher, same algorithm (seed=0, XXH3_128) |
| JSON | stdlib `json` | **serde_json** | Standard Rust serialization |
| Async runtime | Uvicorn/asyncio | **tokio** | Multi-threaded, work-stealing |
| CLI | n/a | **clap** | Subcommands: `serve`, `scan`, `hash-cache` |
| Static files | FastAPI StaticFiles | **tower-http** `ServeDir` | Same mount point `/static` |
| SSE | FastAPI `StreamingResponse` | **axum** `Sse` + `tokio_stream` | Native support |
| URL parsing | `urllib.parse` | **url** crate | RFC-compliant URL parsing |
| Logging | `print()` | **tracing** | Structured, leveled |
| Config | `os.getenv()` | **dotenvy** + `std::env` | Twelve-factor compatible |
| Performance | `time.monotonic()` | `std::time::Instant` | Mono clock |
| Templating | none (SPA serves static) | none (same SPA) | Zero server-side rendering |

## 4. Implementation Phases

### Phase 0: Project Scaffold

- `cargo init rust-scan-library-tool`
- Write `Cargo.toml` with dependencies: axum, tokio, sqlx, reqwest, serde/serde_json, clap, walkdir, rayon, xxhash-rust, url, dotenvy, tracing, tower-http, tokio-stream, uuid, chrono
- Set up `.env` defaults matching `config.py`
- Write `config.rs` (KOMGA_BASE_URL, PG_*, DRY_RUN, EXPORT_DIR, HASH_CACHE_DIR, SCAN_THREADS, HASHER_THREADS)
- Write `models.rs` — struct definitions: `Library`, `DbSeries`, `DbBook`, `FsSeries`, `FsBook`, `FsData`, `Diff`, `ScanResult`, `ScanTimer`, etc.

### Phase 1: Core Logic (no server)

#### 1a — `api.rs` (Komga REST client)
- `list_libraries() -> Vec<Library>`
- `create_series(…) -> SeriesDto`
- `delete_book(id)`, `delete_series(id)`
- `get_series_books(id) -> Vec<BookDto>`
- `empty_trash(lid)`
- `analyze_book(id)`, `refresh_book_metadata(id)`, `refresh_series_metadata(id)`
- Session reuse with reqwest `Client`, basic auth, retry logic (MAX_API_RETRIES)

#### 1b — `db.rs` (PostgreSQL reader)
- sqlx `FromRow` derive on newtypes matching Komga table schema
- `read_libraries()`, `read_series(lid)`, `read_books(lid)`
- `read_unanalyzed_books(lid)`, `read_books_missing_thumbnail(lid)`
- **Critical:** table/column names are case-sensitive in Komga (e.g. `"LIBRARY"`, `"SERIES"`, `"BOOK"`, `"ID"`, `"NAME"`, `"URL"`, `"FILE_LAST_MODIFIED"`)

#### 1c — `walker.rs` (Filesystem walker)
- Recursive directory walk via `walkdir` + parallel via `rayon`
- Filter `.pdf` only (case-insensitive extension)
- Compute `file://` URIs with `Url::from_file_path()`
- Optional XXH3_128 hash via `xxhash-rust` (seed=0, same as Python)
- Hash cache loading (`HashCache` struct from `hasher.rs` → `HashMap<String, CacheEntry>`)
- `on_progress` callback via channel
- Oneshots: root-level PDFs + oneshots_dir PDFs
- Exclusions set support

#### 1d — `hasher.rs` (Hash cache engine)
- Merge pdf-hasher `main.rs` logic into library
- `HashCache` struct (serde) matching existing JSON format
- `HashCacheEntry { hash, size, mtime_secs }`
- `load_cache(path)`, `build_cache(root, cache_path, threads)` — walk + classify + hash in parallel
- `get_hash(uri, cache)`

#### 1e — `diff.rs` (Diff engine)
- Exact port of Python diff logic:
  - `normalize_file_url()` — handle `file:/path`, `file:///path/`, trailing slashes
  - `mtime_equals()` — second-level tolerance, strip sub-seconds & timezone
  - `compute()` — URL-normalized key matching, hash priority over mtime/size
  - `group_new_books_by_series()` — group new books by parent series ID
- `Diff` struct: new_series, deleted_series, new_books, deleted_books, changed_books, pending_hash, to_be_analyzed, no_metadata

#### 1f — `applier.rs` (Curl generator + executor)
- `generate_curl_scripts()` — per-category bash scripts + combined `all.sh`
- `execute_curl_script()` — subprocess execution with progress
- `curl_cmd()` helper building correct curl strings
- `parse_curl_commands()` for execution
- Mirror `_bld_new_series`, `_bld_deleted_series`, `_bld_new_books`, `_bld_deleted_books`, `_bld_changed_books`, `_bld_pending_hash`, `_bld_to_be_analyzed`, `_bld_no_metadata`

#### 1g — `export.rs` (JSON export)
- `export_snapshots()` → J1 (DB) + J2 (FS) JSON files
- J3 diff JSON with `_raw_diff`, `_raw_fs_data`, `_raw_db_series_by_url`

#### 1h — `perf.rs` (Performance)
- `ScanTimer` with phase begin/end/record_phase
- `finish()` returns timing report
- `write_log()` to `request_id_perf.json`

### Phase 2: Web Server

#### 2a — `server.rs` (Axum HTTP)
- State: `AppState` with Config, reqwest Client, sqlx Pool
- Static file serving: `/static` → `tower_http::services::ServeDir`
- SPA fallback: `/` → `static/index.html`

#### 2b — API Endpoints (match Python server.py exactly)

| Method | Path | Python handler | Rust handler |
|---|---|---|---|
| `GET` | `/api/version` | `version()` | `version_handler()` → `{version, title}` |
| `GET` | `/api/libraries` | `get_libraries()` | `libraries_handler()` → `api::list_libraries()` |
| `GET` | `/api/list-requests` | `list_requests()` | `list_requests_handler()` → scan EXPORT_DIR |
| `POST` | `/api/scan` | `run_scan()` | `scan_handler()` → parallel DB+FS → diff → export |
| `POST` | `/api/curl` | `gen_curl()` | `curl_handler()` → read diff JSON → generate scripts |
| `POST` | `/api/execute` | `exec_script()` | `execute_handler()` → SSE stream curl execution |
| `GET` | `/api/exports/{*path}` | `download_file()` | `export_download_handler()` → FileResponse |
| `GET` | `/api/hash-cache/{id}` | `get_hash_cache()` | `hash_cache_info_handler()` |
| `GET` | `/api/hash-cache/{id}/download` | `download_hash_cache()` | `hash_cache_download_handler()` |
| `POST` | `/api/hash-cache/{id}` | `generate_hash_cache()` | `hash_cache_generate_handler()` → SSE stream |

- **SSE endpoints** use `axum::response::Sse` + `futures::stream`
- **Scan endpoint** uses `tokio::task::spawn_blocking` for FS walk + DB reads, parallel via `tokio::join!`
- **Concurrency guard** — `Arc<Mutex<HashSet>>` for in-progress hash generation

#### 2c — CLI Subcommands

```

```

## 5. Key Compatibility Requirements

1. **URL normalization** — must handle all 4 Java DB URL formats:
   - `file:/path` → `file:///path`
   - `file:/path/` → `file:///path`
   - `file:///path` → `file:///path`
   - `file:///path/` → `file:///path`
   - Non-file URLs passed through unchanged

2. **mtime comparison** — second-level tolerance, strip sub-seconds and timezone suffixes

3. **Hash algorithm** — XXH3_128 with seed=0, hex output lowercase 32 chars

4. **Hash cache JSON format** — must match existing `HashCache` struct exactly:
   ```json
   {
     "type": "XXH3_128 hash cache",
     "version": 1,
     "root": "...",
     "generated_at_unix_secs": 1234567890,
     "elapsed_secs": 12.3,
     "total_files": 100,
     "total_bytes": 123456,
     "entries": { "file:///path/to/file.pdf": { "hash": "...", "size": 123, "mtime_secs": 123 } }
   }
   ```

5. **DB queries** — use exact same SQL with case-sensitive quoting

6. **API calls** — same endpoints, same JSON payloads, same auth

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| sqlx compile-time checks require running DB | Use `sqlx::query_as` with runtime-only queries (no `query!` macro), match Python exactly |
| URL crate `from_file_path` differs from Python `Path.as_uri()` on some platforms | Add normalization pass that converts any `file://host/path` to `file:///path` |
| Axum SSE differs from FastAPI SSE format | Test SSE wire format — axum `Sse` produces standard `data: ...\n\n` |
| rayon + tokio blocking conflict | Use `tokio::task::spawn_blocking` for rayon-heavy work to avoid starving async runtime |
| File path character encoding on different OS | Use `OsString` / `Path` throughout, convert to string only for URIs |

9. `server.rs` (Axum server, ties everything together)
