# Plan: Integrate Rust Hash Cache into Komga's scanRootFolder

## Motivation

The Rust binary `pdf-hasher` walks a library root, computes XXH3_128 hashes for all PDF files (~50x faster than Komga's per-book Kotlin hasher), and writes a hash cache JSON. By exporting Komga's DB state to a matching JSON per library, the two files can be diffed to discover what changed — eliminating the need for scanRootFolder's costly filesystem walk and per-series DB lookups.

**Goal**: Run the Rust hasher first (as `Task.HashLibrary`), then in `scanRootFolder()` diff the hash cache against a lightweight DB export to determine new/changed/deleted books — skipping the filesystem walk entirely.

## Architecture

### Task Chain

```
User clicks "Scan" (or periodic trigger)
  │
  ├── [NEW] Task.HashLibrary(libraryId)
  │     │
  │     ├── Spawn: pdf-hasher --root <root> --cache <cacheFile> -j 4
  │     │     ├── Rust walks filesystem (parallel, mmap hashing)
  │     │     ├── Checks each .pdf against existing cache
  │     │     │   ├── size+mtime match → skip (reuse cached hash)
  │     │     │   └── new/changed → compute XXH3_128
  │     │     └── Writes hashes-{libraryId}.json (atomic, tmp+rename)
  │     │
  │     ├── Warning if subprocess fails or times out
  │     └── Fans out → taskEmitter.scanLibrary(libraryId)
  │
  └── Task.ScanLibrary handler
        │
        ├── [NEW] export_db_snapshot  (writes db-snapshot-{libraryId}.json)
        │     └── Single DB query: all non-deleted books + series for library
        │         Serialized to JSON matching hash cache key format
        │
        ├── [NEW] diff_two_files  (compare hash cache ↔ DB snapshot)
        │     ├── New books = in hash cache, not in DB snapshot
        │     ├── Deleted books = in DB snapshot, not in hash cache
        │     ├── Changed books = in both, hash or size differs
        │     └── Unchanged = in both, same hash + size + mtime → skip
        │
        ├── [NEW] apply_diff  (create/update/delete via existing lifecycles)
        │     ├── New series (grouped from new books by directory)
        │     ├── New books in existing series
        │     ├── Changed books → mark media OUTDATED
        │     ├── Deleted books → soft delete
        │     └── Deleted series → soft delete
        │
        ├── sort_and_refresh_series (existing)
        ├── reconcile_sidecars (existing, unchanged)
        └── fan out: analyze/hash empty hash books
```

### Key Design Decisions

- **Single filesystem walk**: The Rust hasher is the ONLY process that walks the filesystem. scanRootFolder NEVER walks files — it reads the hash cache and diffs against DB state.
- **DB snapshot is a cache**: Written once per scan (or reused if `library.lastModified` hasn't changed since last snapshot). Regenerated cheaply from a single query.
- **Diff in memory**: Comparison is two HashMaps, O(n). No per-series DB lookups during scan.
- **Cache location**: `{configDir}/hash-cache/hashes-{libraryId}.json` and `{configDir}/hash-cache/db-snapshot-{libraryId}.json`

## File Formats

### Hash Cache (`hashes-{libraryId}.json`)

Produced by `pdf-hasher`. Flat map of `file:///` URI → entry:

```json
{
  "entries": {
    "file:///data/SeriesA/Book1.pdf": {
      "hash": "a1b2c3...",
      "size": 123456,
      "mtime_secs": 1234567890
    }
  }
}
```

### DB Snapshot (`db-snapshot-{libraryId}.json`)

Produced by Komga from a single SQL query. Flat structure for easy comparison:

```json
{
  "books": {
    "file:///data/SeriesA/Book1.pdf": {
      "id": "book-id-123",
      "seriesId": "series-id-456",
      "seriesName": "SeriesA",
      "seriesUrl": "file:///data/SeriesA",
      "fileHash": "a1b2c3...",
      "fileSize": 123456,
      "fileLastModified": "2024-05-31T12:00:00",
      "number": 1,
      "deletedDate": null
    }
  },
  "series": {
    "file:///data/SeriesA": {
      "id": "series-id-456",
      "name": "SeriesA",
      "libraryId": "lib-789",
      "fileLastModified": "2024-05-31T12:00:00",
      "deletedDate": null
    }
  }
}
```

### Diff Result (internal, not persisted)

```
class ScanDiff(
    newBooks: List<NewBook>,        // new files not in DB
    deletedBooks: List<DbBook>,     // in DB but file deleted
    changedBooks: List<ChangedBook>, // hash/size/mtime differs
    unchangedBooks: List<DbBook>,    // everything matches
)
```

### Diff Logic (pseudocode)

```
hashCache = load("hashes-{libraryId}.json")
dbSnapshot = load("db-snapshot-{libraryId}.json")

hashUris = keys(hashCache.entries)     // file:/// URIs on disk
dbUris = keys(dbSnapshot.books)        // file:/// URIs in DB

newBookUris = hashUris - dbUris
deletedBookUris = dbUris - hashUris

for uri in (hashUris ∩ dbUris):
  h = hashCache.entries[uri]
  d = dbSnapshot.books[uri]
  
  if h.hash == d.fileHash && h.size == d.fileSize:
    unchanged(uri)
  else:
    changed(uri, d.id, d.seriesId, newHash=h.hash, newSize=h.size)
```

### Step 3: Handle `Task.HashLibrary` in TaskHandler

**File**: `komga/.../application/tasks/TaskHandler.kt`

Inject `KomgaProperties`. Handler spawns `pdf-hasher` as subprocess, waits with timeout, then fans out to `Task.ScanLibrary`:

```kotlin
is Task.HashLibrary -> {
    libraryRepository.findByIdOrNull(task.libraryId)?.let { library ->
        val cacheDir = Paths.get(komgaProperties.configDir ?: ".", "hash-cache")
        Files.createDirectories(cacheDir)
        val cacheFile = cacheDir.resolve("hashes-${library.id}.json")
        
        val cmd = listOf(
            "pdf-hasher",
            "--root", Paths.get(library.root.toURI()).toString(),
            "--cache", cacheFile.toString(),
            "-j", komgaProperties.hasherThreads.toString()
        )
        
        val process = ProcessBuilder(cmd)
            .redirectErrorStream(true)
            .start()
        
        val finished = process.waitFor(600, TimeUnit.SECONDS)
        if (!finished) {
            logger.warn { "pdf-hasher timed out for library ${library.id}" }
            process.destroyForcibly()
        }
        
        taskEmitter.scanLibrary(library.id, scanDeep = false, priority = task.priority)
    } ?: logger.warn { "Library ${task.libraryId} not found" }
}
```

### Step 4: Add `DbSnapshotService` — export DB books to JSON

**File**: NEW `komga/.../domain/service/DbSnapshotService.kt`

```kotlin
@Service
class DbSnapshotService(
    private val bookRepository: BookRepository,
    private val seriesRepository: SeriesRepository,
    private val komgaProperties: KomgaProperties,
) {
    fun export(libraryId: String): DbSnapshot {
        val series = seriesRepository.findAllByLibraryId(libraryId)
            .filter { it.deletedDate == null }
            .associateBy { it.url.toString() }
        
        val books = bookRepository.findAllBySeriesIds(series.keys)
            .filter { it.deletedDate == null }
            .associateBy { it.url.toString() }
        
        return DbSnapshot(
            books = books.mapValues { (url, book) ->
                val s = series[book.seriesId] ?: series.values.first { it.id == book.seriesId }
                DbBookEntry(book, s)
            },
            series = series.mapValues { (_, s) -> DbSeriesEntry(s) },
        )
    }
    
    fun write(libraryId: String, snapshot: DbSnapshot) { ... }
    fun load(libraryId: String): DbSnapshot? { ... }
}
```

### Step 6: Rewrite `scanRootFolder()` to use diff-based approach

**File**: `komga/.../domain/service/LibraryContentLifecycle.kt`

New phases replacing `filesystem_scan`, `delete_missing`, and `reconcile`:

```
Phase 1: "export_db_snapshot" → DbSnapshotService.export(libraryId)
Phase 2: "load_hash_cache"     → HashCacheService.load(libraryId)
Phase 3: "diff"                → ScanDiffer.diff(hashCache, dbSnapshot)
Phase 4: "apply_diff"          → Apply creates, updates, deletes
Phase 5: "sort_and_refresh"    → Existing logic
Phase 6: "reconcile_sidecars"   → Existing logic
Phase 7: "cleanup"             → Empty trash etc.
```

The diff tells us exactly what to do — no filesystem walk, no per-series DB lookups.

## Graceful Degradation

| Scenario | Behavior |
|----------|----------|
| `pdf-hasher` binary missing | Log error, skip, proceed to scan |
| Hasher times out (10 min) | Kill, log warning, proceed to scan |
| Hash cache file missing/corrupt | Log, proceed with traditional filesystem scan as fallback |
| DB snapshot outdated | Regenerate from DB (single query, fast) |

---

## Performance Comparison

| Phase | Current (walk + reconcile) | New (hash cache diff) |
|-------|---------------------------|----------------------|
| Filesystem walk | 30-60s (Java, single-threaded) | 5-10s (Rust, parallel, mmap) |
| DB load (existing books) | Per-series queries | Single query → JSON (1-2s) |
| Diff/compare | Per-series O(n×m) with DB lookups | Set-based O(n) in memory (1-2s) |
| Apply changes (create/update) | Same | Same (10-20s) |
| **Total (10K books)** | **~50-100s** | **~20-40s** |
